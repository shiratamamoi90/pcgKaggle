## 2. 効いた3つ

### (a) 教師の質 — ただし「量」に化けた
段階1→2の跳躍（46% → ~832）は、**弱い自分ではなく強い他人を模倣**したことによる。
ところが 08-02 に測り直すと、**教師が誰かは効かず、効いていたのは教師データの量**だった。
同量なら純度は 0.3pp（純教師 57.9% vs 混合 58.2%）、18チーム混合でも 58.8%。

**飽和量は約 5,000 サイド**（3,586→49.2% / 5,156→57.9% / 6,925→55.7%）。
そして 08-05 に全デッキ・7日3万試合を走査した結果、
**飽和量に届く単独教師はラダー上のどこにも存在しなかった**（最多 1,142サイド = 23%）。
→ **「もっと良い教師を探す」という軸は、探索の結果ではなく供給量で閉じた。**

### (b) 貪欲推論（探索を切ること）
MCTS を積むと**弱くなる**。budget 1 → 30 で FIELD14 指標が **+27.3pp・14/14の相手で勝ち・z=9.14**。
budget 1→4→16 でも 66.7 → 53.0 → 46.7% と単調悪化。

当初は「価値ヘッドが粗いせい」と診断して復活の芽を残していたが、
value損失を −56% 改善した新ネットで再検定しても `NN_SEARCH=1→8` が
**64.0%→38.0%（z≈−5.4）**と同じだけ壊れた。**価値ヘッドは律速ではない。**

原因は隠れ情報。相手のデッキ・手札・サイドを雑に仮定したロールアウトが、
BCで得た良い方策を上書きする。**不完全情報ゲームでは、方策が十分良いとき探索は純粋な劣化要因になりうる。**

### (c) 重み平均（同一basin限定）
`out = a·A + (1-a)·B` は**同一初期値から派生したモデル同士でのみ**有効。
独立にBCしたモデル同士（cross-basin）は **実測 0.0% で完全崩壊**した。

## 4. ★ 測定の失敗史（本レポートの核心）

**このプロジェクトで最も高くついたのは、アルゴリズムの失敗ではなく測定の失敗である。**
以下は全て、当時「確認済み」と思っていたものが後から崩れた実例。

### (a) ラダーには検出下限がある — 76 Elo
**同一バイトの tar を繰り返し投げると sd ≈ 27 で散る**（champion n=5 / soup n=3 で独立に一致）。
差分の sd は ≈38、したがって**単発ペアの 2σ 検出下限は約 76 Elo**。

**これまでのラダーA/Bは全部この下限を下回っていた。** 「+20.4 で前進」も「clean9 が2点的中」も
「FRESH7 が 2/2」も、**全部ノイズの上の議論**だった。
弱いモデル帯ではさらにひどく、同一tarが 810 / 575 / 704（sd 118）に散る。

→ **帰結: オフライン指標を1ペアのラダー実験で較正する、という手続き自体が成立しない。**
較正には同一ペアの5〜10反復が要るが、1日5提出・追跡latest-2 では1候補に1〜2週間かかる。

### (b) オフライン指標はデッキ乗り換えの成否を一切予測できない
2度、上位メタデッキ（Marnie's Grimmsnarl ex）へ乗り換えるクローンを作った。

| クローン | オフライン評価 | ラダー実測 |
|---|---|---|
| luca_solo | 対champion h2h **58.1%**（n=2,400, 8.0σ） | **−259.4 Elo** |
| metapool | 帯加重で champion **+5.1pp**、アーキタイプ実勝率を **0.7pp 差で再現** | **−186.1 Elo** |

metapool は失敗作ではない。**実ラダーのアーキタイプ勝率を 0.7pp で再現した唯一のクローン**であり、
h2h でも帯加重でも champion を上回っていた。**それでも 186 Elo 負けた。**
しかも luca_solo は metapool に h2h 53.5% で勝つ＝**より良く見える方が、より大きく負けた。**

→ **どんなオフライン数値も、デッキ乗り換えの成否について情報を持たない。指標を作り替えても解決しない。**

### (c) 忠実度は強さの代理ではない
BCの天井が「教師をうまく真似られていないから」だと仮定し、容量とエポックを分離して測った。
訓練CE −29% / 価値損失 −56% / 教師との一致率 +2.8pp（z≈4.3で有意）と**忠実度は全部改善した**。
**ミラー h2h は 48.0% / 52.5% ＝ 強さはゼロ変化。全指標で最良の腕が実戦では最下位だった。**

→ **一致率（agreement rate）を play strength の代理指標に使ってはいけない。**
教師との 325 Elo 差は、模倣誤差でも探索の欠如でも説明されない。

### (d) 蒸留先が蒸留元より弱いことに2ヶ月気づかなかった
RLが10回連続で null だった原因は、ハイパラでも報酬設計でもなかった。
方策のターゲットが **budget 10 の MCTS 訪問分布**だったが、
champion は @budget10 で **64.1%**、@budget1 で **85.7%**。
**ターゲットが生徒より 21.6pp 弱かった。**

→ **一般則: 自分より強いものからしか蒸留できない。** BCが効いたのは教師が強かったから。
10回ぶんの失敗が、この1つの構造的欠陥に還元された。

### (e) シミュレータが 42.4pp 嘘をついていた
評価用の対戦相手 `opponents/grimmsnarl` は **07-06 製**だった。
**デッキは現行メタと 58/60 一致していたため、古さが見えなかった。**
実ラダー 3,408試合では我々のアーキタイプは grimmsnarl に **43.6% ＝ 負け越し**だが、
シミュレータは同じ組合せを **86.0%** と報告していた。**差 42.4pp。**

これにより、それまでのオフライン指標・「championは天井で改良余地なし」という判断・
外部エージェント戦に依存する結論が**まとめて無効になった**。

→ **相手エージェントは「デッキが合っているか」でなく「方策がいつのものか」を見る。**

### (f) 沈黙する初期化バグ
`main_nn.py` は `load_state_dict` の失敗を try/except で握り潰し、
**ランダム初期化のまま推論を続ける**。警告は stdout のみ＝`2>/dev/null` で不可視。
ある候補の 26.6% はこれが原因で、正しいアーキテクチャを明示すると **61.9%** だった。

### (g) 作業ディレクトリのバグで、相手が我々のデッキを回していた
ハーネスが import のときだけ chdir していたため、遅延読み込みの相手エージェントが
**ルートの `deck.csv`（＝我々のデッキ）を読んでいた**。
`archaludon` / `archaludon_masa` は開始以来ずっとこのキメラで、
記録済みの評価結果は全モデルぶん無効になり、RL訓練も汚染されていた。

### (h) 評価スクリプトの二重起動
同一モデル・同一相手で **56.6% と 41.0%** が記録された。
CPU の奪い合いと同一ファイルへの追記が原因。

## 5. リーサル見逃しは「ミス」ではなく「判断」だった

championはKO可能な36回のうち29回（80%）を見送る。**明白なバグに見えた。**
強制的に取らせる改造を入れ、対照群を置いて測った。

| 条件 | 勝率 |
|---|---|
| champion（無改造） | 44.7% |
| 探索呼び出しのみ（判断は上書きしない） | 41.7%（ns） |
| **リーサル強制上書き** | **28.3%（z=−3.33）** |

**探索を呼ぶこと自体は無害で、害は判断を上書きした部分に集中していた。**
ポケカでは攻撃がターンを終えるため、**KOできても見送るのが正しい局面が実在する**。

→ **「人間から見て明らかなミス」を修正する前に、対照群を置いて測ること。**

`episodes/` は 07-26〜08-01 の実ラダーリプレイ7日分。**これは Strategy レポートの一次データになる。**

- **上位帯は単一の60枚リストに収束していた**: Marnie's Grimmsnarl ex を

  grimmsnarl **58.4%** / other **29.2%（97種に断片化）** / alakazam **9.4%**。

- 改良余地があったのは other 29.2% だけだが、97種に断片化しており上位2種で 6.5% しかない。

## 7. Strategy レポートに書ける主張（候補）

1. **不完全情報ゲームでは、良い方策に対する探索は劣化要因になりうる**（§2b・実測 +27.3pp / z=9.14）
2. **模倣忠実度は play strength の代理にならない**（§4c・忠実度全指標改善で強さ 0 変化）
3. **自分より弱いターゲットからは蒸留できない**（§4d・10回の失敗が1つの原因に還元）
4. **オフライン評価はデッキ乗り換えを予測できない**（§4b・0.7pp 精度の再現でも −186 Elo）
5. **Elo ラダーには検出下限がある**（§4a・同一バイトで sd 27、単発ペア 2σ = 76 Elo）
6. **評価用対戦相手の「鮮度」は「デッキ一致」では測れない**（§4e・58/60一致でも 42.4pp のズレ）
7. **人間から見た明白なミスが最適な判断であることがある**（§5・リーサル見逃し 80%）
8. **メタは単一リストに収束していた**（§6・175チームが 60/60 一致）

**このプロジェクトの提出可能な価値は「強いエージェント」ではなく、
「何が効かないかを、対照群を置いて50提出ぶん測り切った記録」の側にある。**
