# 評価軸 (eval-axes.md)

> **更新（2026-06-21）:** 実測で「対トップボット計測は分散が巨大」「AIが主ボトルネック」等が判明したため、
> 実運用の方針と評価軸は **`docs/strategy.md`** に再整理した。本ファイルは初期の評価軸カタログとして残す。
> A/B は random/first を主指標に N≥400 で測ること（詳細は strategy.md 3章）。

公式ラダーは **Elo（勝敗のみ）** で順位を決める。スコアの中身は採点されない。
以下は「なぜ勝った/負けたか」を理解し改良するために**自分で計測する**軸。

## 1. 対戦の基本メトリクス

| 指標 | 意味 | 取り方 |
| --- | --- | --- |
| 勝率（相手別） | アーキタイプ別にどれに勝ち/負けるか | 相手デッキごとに集計 |
| 平均ターン数 | 速攻型か粘り型か。デッキの健全性 | 各試合のターン数を平均 |
| 先攻/後攻別勝率 | 先後の影響が大きいので分離 | 先攻時・後攻時で分けて集計 |
| 勝敗時の平均サイド差 | 圧勝か辛勝か、負け方の質 | 終局時のサイド枚数差 |
| 引き分け/時間切れ率 | エンジン制限に当たっていないか | 引き分け試合の割合 |

最低でも数百〜1000試合回す。少ないと運に埋もれて差が見えない。

## 2. デッキ評価（メタ視点）

- **相性マトリクス**: 自デッキ × 各相手デッキの勝率表。
- **メタ内期待勝率**: 相性表にメタ分布（各デッキの存在比率）を重み付けした総合勝率。
- **じゃんけん構造**: 何に強く何に詰むかの相性地図。
- **トレーナーズの役割分類**: ドロー/サーチ・エネルギー・妨害・回復・入れ替え・どうぐ・スタジアム。
  デッキの事故率評価につながる。

## 3. 判断の質（最も改良に効く）

勝敗から切り離して「個々の意思決定が良かったか」を測る。

- **行動の合意率**: 人間が明らかに最善と思う局面でエージェントが同じ手を選ぶ割合。
- **致命的ミス頻度**: 無償退却でサイドを取られる、リーサル見逃し等の明確な悪手のカウント。
- **リソース効率**: 無駄なトラッシュ落とし、キーカードを引けなかった率、ベンチ枚数推移。
- **盤面評価関数の検証**: agent内に盤面スコア関数を持たせ、そのスコアと実際の勝敗の相関を見る。

## 4. 探索を入れる場合（上位狙い）

- cabt の探索API（`search_begin` / `search_step` / `search_end`）で、
  「この手を選んだ後の盤面がどれだけ良くなるか」を先読みスコアで評価できる。
- ルールベースを超える段階。フェーズBが安定してから着手する。

## 計測の優先順位（おすすめ）

1. まず「勝率・平均ターン数・先後別・サイド差」を吐くスクリプトを作る。
2. 改良はすべてこの数字で A/Bテストして判断する。
3. 慣れたら相性マトリクス → 判断の質 → 探索、の順で深める。
