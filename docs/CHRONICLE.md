# 第0期 — 立ち上げ（06-20 〜 06-27）

## 1. valid submission を1回通す

- **目標**: フェーズA。エージェントの強さは問わず、提出が受理される状態を作る。
- **実施**: 公開サンプル（メガルカリオex）の `main.py` と `deck.csv` を流用し、
  `tar -czf submission.tar.gz *` でバンドル。`kaggle competitions submit` で投入。
- **結果 ✅**: 受理。ただし**提出物にネスト禁止**という制約が効いており、
  ディレクトリごと固めると Validation Episode で落ちることを実地で確認。

- **次の手順**: `tar -tzf` によるネスト確認を提出前の必須手順に格上げ。
  以降50本すべてでこの確認を実行した。

## 2. ルールベースの改良（v2 〜 v17）

- **目標**: if 文の条件分岐を1点ずつ足して勝率を上げる。
- **実施**: 退却判断・エネルギー配分・ベンチ選択などを16世代ぶん改良。
- **結果 ⚠️ 頭打ち**: ラダー **~450〜570** で停滞。改良を足しても伸びない。
- **判断**: ルールベースの天井が低いと結論。**NN へ移行**。

## 3. 自己BC + 自己対戦RL

- **目標**: 自分の手を模倣して初期方策を作り、自己対戦の強化学習で伸ばす。

- **原因**: **自分を真似ても自分止まり**。初期値が天井を決めていた。
- **次の手順**: 教師を「自分」から「強い他人」に切り替える。この転換が最大の分岐点になった。

## 6. モデルスープ（重み平均）

- **目標**: 複数モデルの重みを平均して無料で伸ばす。

- **不具合 ❌**: **cross-basin（独立にBCしたモデル同士）は実測 0.0% で完全崩壊**。

## 17. ★ 測定器の間欠故障を発見（multiply_lucario）

- **目標**: アンカーとして使っていた `multiply_lucario` への勝率が再現しない理由を突き止める。
- **最初の説明（誤り）**: この相手は壁時計1.5秒の探索予算を持つので負荷依存だろう。
  workers 1/4/12 で **83.0 / 13.0 / 16.0%** と出たので裏付けたつもりになった。
- **反証**: `USE_SEARCH=False` でも workers=1 で 86.0%、探索ONのまま workers=4 でも 84.0%。
  **並列度は原因ではない。**
- **同一条件の反復（これが決め手）**: workers=4・n=100 を6回:
  ```
  81.0% / 86.0% / 15.0% / 87.0% / 81.0% / 81.0%   ← 二峰。勾配ではない
  ```
- **真の機構（証明済み）**:
  1. `multiply_lucario/main.py:39` が **import時に cwd へ `deck.csv` を書き**、`:55-57` で読み返す
     （`opponents/` 12体でこれをやるのはこの1体だけ）
  2. Pool worker が同時 import すると、1つが **truncate中のファイルを読んで `my_deck = []`**
  3. その worker の相手は不正なので**担当した全試合で相手のリワードが `None` ＝ forfeit**
  4. forfeit 試合は一瞬で終わるので、**壊れた worker がタスクキューを食い荒らす**（100戦中86戦が影響）
  5. `h2h_vs_rule.py` の `_play` が `b is None` を **`return 0`＝こちらの負けと集計**
     — **相手の自滅を我々の敗北として数えていた。符号が逆。**
- **修理**: `_load_mod` で `fcntl.flock` により import を直列化、`_play` は forfeit / draw を
  分離して率から除外し警告を出す。
- **修理後**: 10回反復で forfeit 0/10・**72〜83%（平均78.2, sd≈3.8）＝単峰に収束**
  （修理前は16回中8回が壊滅、Fisher p<0.005）。
- **無効になったもの ❌**: 記録済みの multiply_lucario 値すべて（79 / 20 / 18 / 24 / 92.5 / D1の16 / D2の75）。
  「6日版だけが固有の頑健性を持つ」も「D1は地雷」も「workers=12の競合状態」も**全て誤り**。
- **★この節自体が教訓**: 条件を変えた反復だけでもっともらしい因果を立て、
  **同一条件の反復を省いたために誤った結論を一度記録した**。
  → 恒久ルール化: **説明を思いついた時ほど同一条件で反復する。**
