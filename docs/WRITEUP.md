# 測定器の失敗史と8つの一般則

### 50提出・48施策を対照群つきで測り切った記録—ポケカAI Battle Challenge

参加者shiratama（dotshiratama・個人参加）/Simulationカテゴリ2026-06-20から08-16

「強くなった」と記録した結論が、数日後に自分の測定器の欠陥として崩れ続けた。この現象は8回起きた。存在しない差を見て候補を選抜しており、最大でシミュレータが実ラダー（提出したエージェント同士を対戦させ続ける公式の対戦環境）と42.4パーセントポイント（pp）ずれていたこともあった。

---

## 1. 結果

スコアは819.4、995位/6,807チーム（上位14.62%）、提出50本・施策48件。これは2026/09/21に確定した値である。提出時点では2026/08/17 11:23の暫定値846.1、673位/6,892チーム（上位9.8%）と記載しており、締切後もラダーが対戦を続けた結果ここまで下がった。

本レポートは何が効かないかを、対照群（比較のために同時に測る変更前の条件）つきで50提出分測った記録である。48件の内、有意に改善したものは0件、有意に悪化したものは2件、null（有意な差が出なかった結果）は10件以上、測定器の欠陥として発見したものは8件、撤回した自分の結論は10件以上ある。

---

## 2. 手法と最終成果物

方策は小型Transformer（AlphaZero系2ヘッド）。エンコーダが盤面を読んで価値（その局面から勝つ見込み）、デコーダが候補手を読んで方策を出す。d_model=128, heads=2, ff=256, enc=1, dec=1で、総パラメータ12.53Mのうち98%が埋め込み（カードなどの記号を数値ベクトルに置き換えた表）、本体は0.265M。カードは(index, value)の組み合わせにしてEmbeddingBagで加算するので、集合情報が順序非依存になり、与える打点のような自明な量はニューラルネットワーク（NN）に再発見させずデコーダへ直接渡す。

学習は行動クローニング（BC。教師の指し手をそのまま真似る教師あり学習）1本。教師はラダー1位チームのリプレイ4,755サイド（サイドは1試合を両プレイヤーそれぞれから1件と数えた単位）/428,461サンプル、12エポック（訓練データを1周すること）。強化学習（RL）は4形態・10回以上試して全てnullだった。推論は貪欲（最も確率の高い手をそのまま選ぶこと）で、探索は切っている（5.1節）。以下の分析は全て、実ラダーのリプレイ7日分145GBの実測から出ている。

ルールベースは450〜570で頭打ち、自己BCと自己対戦RLは46%で停滞した。教師を「自分」から「強い他人」に替えた瞬間に832になった。1位チームをその正デッキ上で模倣して934、教師データ3.09倍で938.8。以降11回の改良試行は1件も転移しなかった。

---

## 3. デッキ

Alakazam ex + Dudunsparce（フーディンex＋ノココッチ）。構築は行わず、教師の60枚をそのまま使った。

戦略を「上位プレイヤーの方策の模倣」に置いた以上、デッキはその従属変数になる。1枚でも動かせば教師データの外の局面が生じ、模倣の前提が崩れる。デッキと方策の整合を、新規性より優先した。支配的アーキタイプ（同じ勝ち筋を持つデッキの型）へ乗り換えるクローン（他チームの対戦記録を模倣して作ったモデル）を2回作り、2回とも大敗した（−259.4と−186.1 Elo。Eloは勝敗だけで決まる持ち点で、公式ラダーの順位はこれで決まる。5.5節）。

60枚は22種、うち9種が4枚採用（36枚＝60%）。初期状態に依存せず同じ勝ち筋を反復する構成で、これは方策側の要求と一致する。BCは分岐の多い構築より、安定した1本の勝ち筋のほうが写しやすい。

実ラダー61,994サイドの構成は、オーロンゲ（Marnie's Grimmsnarl ex）58.4%、その他29.2%（97種に断片化）、フーディン（私）9.4%。フーディンを使う20チーム全員がオーロンゲに負け越しており（最高49.7%、教師本人でも49.2%）、フィールド（ラダー上の相手デッキの構成）で加重すると10種中9位の45.4%、首位のオーガポンは64.5%である。完璧に模倣できても上限は49.2%だった。このデッキは強かったから選ばれたのではなく、教師が使っていたから選ばれた。

三すくみも実在する。オーガポンはオーロンゲに86.0%（nは試合数。n=637）、オーロンゲはフーディンに56.4%、フーディンはオーガポンに79.2%（n=48）で勝つ。それでもオーロンゲの78.7%は175チームが共有する単一のリストだった。この環境ではデッキ構築が事実上終わっており、差は方策側にしか残っていなかった。

## 4. 効いたこと・失敗したこと

効いたのは3つである。教師の質は46%の壁を破ったが、これは後にデータ量だと分かった（同量なら純度差は0.3pp、約5,000サイドで飽和）。貪欲推論は+27.3pp・14/14の相手で勝ち・z=9.14（zは差が偶然で説明できる範囲からどれだけ離れているかを表す値）。重み平均は同一basin（損失地形の同じ谷）内なら無料で伸びる一方、独立に学習したモデル同士は0.0%で完全崩壊する。効かなかった軸は10以上あり、RL4形態、教師プール化、BC容量増、勝ち局限定BC、リーサル（相手を倒しきれる打点）の強制取得、デッキ移植、ロジット・アンサンブル（複数モデルの出力を平均して1手を選ぶこと）が含まれる。

最も高くついた失敗は、測定器そのものの欠陥だった。

| 欠陥                                                     | 被害                                                                 |
| -------------------------------------------------------- | -------------------------------------------------------------------- |
| 相手の方策が1か月古い                                    | 実ラダー43.6%を86.0%と報告                                           |
| 相手の自滅を自分の敗北と集計                             | 同一条件で81 / 86 / 15 / 87 / 81 / 81%                               |
| 沈黙する初期化バグ                                       | ランダム重みで推論。26.6%が実は61.9%                                 |
| 蒸留（強い側の出力を教師にして学習）の対象が生徒より弱い | RL 10回連続nullの唯一の原因                                          |
| ラダー自体の検出下限                                     | 同一バイトのtar（提出物一式をまとめた書庫）が標準偏差（sd）≈27で散る |

## 5. 考察

### 5.1 改善の条件

RLの10回のnullには1つの原因があり、それはハイパーパラメータでも報酬設計でもなかった。方策ターゲットが探索予算（1手あたりに探索を回す回数）10のモンテカルロ木探索（MCTS）訪問分布（探索が各手を何回選んだかの分布）だった。

| 探索予算 | 勝率  | 用途             |
| -------- | ----- | ---------------- |
| 1        | 85.7% | 提出物全て       |
| 10       | 64.1% | RL訓練ターゲット |
| 30       | 58.4% | ローカル既定     |

ターゲットが生徒より21.6pp弱かった。

自分より弱いものからは蒸留できない。

この1文が3つの結果を説明する。BCが効いたのは教師が強かったからで、RLがnullだったのはターゲットが弱かったから、そしてMCTSが有害だったのは、相手のデッキ・手札・サイドを推測したロールアウトが、現実には起こらない盤面の上の価値を返すからである。方策が十分良くなると、探索が持ち込むバイアスが、除去する誤差を上回る。

一度これを価値ヘッド（価値を出力する側の出力層）のせいだと考え、価値損失を−56%改善し再検定した。結果は64.0%が38.0%に落ち（z≈−5.4）、価値ヘッドは律速（全体の限界を決めている要因）ではなかった。そしてこの結論は14体の相手全てで同符号（z=9.14）であり、特定のマッチアップに依存した観測ではない。AlphaZero系は探索が方策を改善することを前提にするが、それは測るべき仮定であって与件ではない。

### 5.2 忠実度は強さの代理にならない

BCの天井が模倣精度で決まると仮定し、容量とエポックを分離して測った。訓練の交差エントロピー（CE）−29%、価値損失−56%、教師一致率（同じ局面で教師と同じ手を選ぶ割合）+2.8pp（z≈4.3）と、忠実度は全指標で改善し、同型戦の勝率は48.0%と52.5%＝動かなかった。全指標で最良が実戦では最下位だった。

対照が機構を示した。チャンピオンは自分の教師に78.5%、同じデッキの別チームにも70.2%一致する。教師固有の上乗せは+8.3ppしかない。判断の約7割は実質的に強制される手なので、勝敗を決める区間は残りの一部でしかなく、平均指標はそこをほとんど重み付けしない。教師（1252.8）とクローン（~914）の325 Elo差は、模倣誤差でも探索の欠如でも説明されない。共変量シフト（訓練時と本番で入力の分布がずれること）が疑わしいが、検定には教師へのオンライン問い合わせが要る。

### 5.3 オフライン測定器には半減期がある

評価相手は07-06製で、デッキが現行メタと58/60一致していたため、古さが見えなかった。実測43.6%（n=3,408）に対し、シミュレータは同じ組合せを86.0%と報告した。勝ち越していると思っていた相手に、実は負け越していた。これで「チャンピオンは天井」という判断も、外部エージェントに依存する結論も全て無効になった。機構は単純で、カードリストは静的だが、方策は静的ではない。

評価相手は「デッキが合っているか」ではなく「方策がいつのものか」で見る。測定器の半減期を決めるのは、メタの適応速度である。

気づけたのはシミュレータを使わない基準を持っていたからで、リプレイからアーキタイプ間の勝率を集計した（30,997試合）。自チームはn=6だが、アーキタイプ同士なら自チームは不要で数万試合が使え、全ての同型戦がちょうど50.0%になることで妥当性が自己検証できる。

測定器の妥当性は、その内部からは検証できない。外部基準を1つ持つ。

作り直した相手は実ラダーを0.7pp差で再現し、限界が常にデータ量だったことも実証された（1,416サイドで約48%、6,925サイドで55.7%、実物が56.4%）。アルゴリズムではなく供給量だった。

### 5.4 反復対戦の安定性と検出下限

同一バイトのtarを繰り返し提出して、安定性を直接測った。

| tar（バイト同一） | n   | ドロー（1回の提出で付いたスコア）     | 平均  | sd   |
| ----------------- | --- | ------------------------------------- | ----- | ---- |
| チャンピオン      | 5   | 936.7 / 980.4 / 976.0 / 945.0 / 917.8 | 951.2 | 26.6 |
| 重み平均          | 3   | 938.0 / 973.5 / 921.1                 | 944.2 | 26.7 |

中身が同一でもsd≈27。差分はsd≈38なので、単発ペアで検出できるのは約76 Elo以上だけで、これまでのラダーA/Bは全てこの下限を下回っていた。閉じるのは個別の実験ではなく方法論である。判定したい効果量（+30 Elo級）が分解能を下回る以上、1ペアでオフライン指標を較正する手続きは成立しない。

同じ過小評価は最後にも起きた。締切24.6h前に両枠（ラダーが追跡する最新2提出の枠）を入れ替えた結果は846.1 / 817.3で、過去6ドロー（平均944.7）から3.7σ（標準偏差3.7個ぶん）下。高い方の枠は確定値では819.4まで落ちた。フィールドは平坦だった。n=6で見積もったsdを信用しすぎた。

### 5.5 オフライン評価はデッキ乗り換えを予測できない

| クローン | オフライン評価                       | ラダー     |
| -------- | ------------------------------------ | ---------- |
| 1回目    | 対チャンピオン58.1%（n=2,400, 8.0σ） | −259.4 Elo |
| 2回目    | アーキタイプ実勝率を0.7pp差で再現    | −186.1 Elo |

2回目は失敗作ではない。実ラダーの勝率を0.7ppで再現した唯一のクローンで、どのオフライン指標でもチャンピオンを上回っていた。それでも186 Elo負けた。1回目は2回目に53.5%で勝つ。より良く見えるほうが、より大きく負けた。1回目は重み・md5・60枚全ての一致を再検証済みで、正常に動作する個体である。

仮説はこうである（未検定であることを明記する）。アーキタイプ行列が測るのは「そのアーキタイプの全使用者の平均」なので、それを自分の期待値に使うのは、自分が平均的な熟練度で操縦できるという仮定に等しい。このクローンは教師プール外のチームにも66.3%一致する＝平均的な使い手を学んでおり、移植先では試合の58.4%が同型戦（同じデッキ同士の対戦）になる。同型戦は方策の質の差がそのまま出る場所である。

デッキ選択の効果量は19.1pp、対してデータ増は2,000サイドあたり+0.6pp、忠実度改善は0pp。最も効果量の大きい変数だけが、測れなかった。

そうと分かった時点でやるべきことは、指標を作り直すことではなく、測れないまま賭けるかどうかを決めることだった。

### 5.6 人間の直観の扱い

チャンピオンはノックアウト（KO）可能な36回のうち29回（80%）を見送る。明白なバグに見えた。修正する前に、対照群を置いて測った。

| 条件                                   | 勝率                    |
| -------------------------------------- | ----------------------- |
| 無改造                                 | 44.7%                   |
| 探索呼び出しのみ（判断は上書きしない） | 41.7%（有意差なし＝ns） |
| リーサル強制上書き                     | 28.3%（z=−3.33）        |

修正すると−13.4ppで有意に悪化した。探索を呼ぶこと自体は無害で、害は判断を上書きした部分に集中していたので、計算コスト等の交絡は排除できる。機構はルールにある。攻撃がターンを終えるため、KOを取ると相手に手番を渡す。KOできても見送るのが正しい局面が実在する。

人間の事前分布をハードな制約として方策に注入する前に、対照群を置いて測る。

この環境で戦う人へ。相手エージェントの製造日を見る。シミュレータを使わない外部基準を1つ持つ。判定基準を事前登録する。説明を思いついた時ほど同一条件で反復する。「明らかなバグ」を直す前に対照群を置く。そして撤回した結論を記録から削除しない。撤回の記録それ自体が、主張がデータで裏付けられている証拠になる。

2か月間、進歩を律速していたのはアルゴリズムでも計算資源でもなく、自分の測定器が嘘をついていることに気づけないことだった。そして測定器の嘘は、必ず「良い結果」の形をして現れる。
